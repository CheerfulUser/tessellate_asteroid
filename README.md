# TESSELLATE asteroid rotation periods and shape models

Rotation periods, phase-folded lightcurves and convex shape models for asteroids observed by
TESS in sectors 27-55, derived from the TESSELLATE reduction.

## Layout

| path | contents |
|---|---|
| `pipeline/` | catalogue generation: period search, reliability scoring, folded-curve products |
| `analysis/` | LCDB reconciliation, label auditing, classifier training |
| `shape/` | convex inversion (DAMIT `convexinv`) and the interactive viewer builder |
| `data/tables/` | small tracked data products (see below) |
| `web/` | public site (GitHub Pages) |

Bulk data -- per-object lightcurves, figure sets, the full catalogue CSV -- is **not tracked**;
see `.gitignore`. It is regenerated by the pipeline on ozstar.

## Data tables

- `lcdb_updated.csv` -- the LCDB summary table with a `period_updated` column carrying TESS
  precision where warranted. Native `Period` is never overwritten; `period_source` records the
  provenance of every row.
- `vetted_lcdb_errors.csv` -- 172 literature periods confirmed by eye to be wrong.
- `label800_labelled.csv` -- 800 hand-vetted objects ("is this period believable"), the only
  labels independent of LCDB.
- `v4_training_table.csv` -- version-independent training data with a frozen dev/test split.

## Reproducing the model

Models are **not** shipped as pickles: a laptop-trained joblib fails to load on ozstar
(numpy 2.5.3 vs 1.26.4). Export the table, then retrain on the machine that will run it:

```
python analysis/export_v4_training.py      # -> data/tables/v4_training_table.csv
python analysis/train_v4_ozstar.py         # on ozstar
```

The dev/test split is frozen into the table so held-out metrics are comparable across machines.
Held-out test (200 objects, never seen in fitting or threshold selection): precision 87.7%,
recall 92.6%, AUC 0.9792.

## Shape models

Production convex inversions use **`NROWS=6`, `HARM=6`** (~289 facets), matching (75) Eurydike.
Set via `CI_NROWS` / `CI_HARM`.

Single-apparition data does not constrain the pole: solutions from different starting poles
scatter by 100 degrees or more. The shape is meaningful, its orientation is not, and
`lambda_circ_std_deg` records that on every solution.
